# לנצ'סטר · מעבדת הליבה

**האפליקציה:** https://claude.ai/artifact/1tTftT3T7L7p67ofNzvfc9

מורה פרטי שמלמד את הליבה הטכנית הצבאית מתוך הספרייה שב-`library/military/`, מודול אחר מודול, לפי תוכנית הלימודים (`library/military/syllabus/`). כמו מעבדת הלמידה, הדף רץ כ-Artifact ב-claude.ai: אין שרת ואין מפתח API, והוא פונה ל-Claude דרך `claude.use("sample")` ומבקש את Claude Opus 5.5. כללי הלימוד נמצאים ב-[`src/prompt.ts`](src/prompt.ts) ובעברית ב-[`docs/CORE_TEACHING_RULES.md`](../../docs/CORE_TEACHING_RULES.md).

## איך זה עובד

- **מפת המודולים:** 169 מודולים ב-14 חלקים. לכל מודול יש מצב: נלמד, זמין או נעול. אפשר להיכנס רק למודול שכל הדרישות המוקדמות שלו נלמדו, ולחיצה על מודול נעול מראה מה חסר.
- **כניסה למודול:** בכניסה הראשונה המורה מחלק את המודול לשיעורים לפי הסעיפים שבעמודי המקורות (`planModule` ב-`src/tutor.ts`). האפליקציה בודקת שני דברים: שכל סעיף שויך לשיעור, ושכל עמוד של מקור ראשי או השלמה נמצא בטווח העמודים של שיעור כלשהו. אם משהו חסר, המורה מקבל הזדמנות לתקן, ומה שעדיין חסר מצורף לשיעור הקרוב ומוצג בדף המודול.
- **שיעור:** לכל שיעור יש שיחה משלו. השיעור נכתב בחלקים: קריאת תכנון ואחריה קריאה לכל חלק (`composeLesson`). התשובה נשמרת כטיוטה תוך כדי כתיבה, וכפתור "המשך" ממשיך שיעור שנקטע מהחלק הבא.
- **נלמד:** שיעור שנכתב עד הסוף מסומן כהושלם. כשכל השיעורים של מודול הושלמו, המודול מסומן כנלמד, והמודולים שתלויים בו נפתחים.
- **מבחן מסכם:** לכל מודול. הציון נשמר במודול.
- **מקורות:** תגית עמוד (`[[B02:115]]`) מוצגת כ"POMR I · עמ' 78". לחיצה עליה פותחת את מציג המקורות בצד, עם טקסט העמוד, האיורים שבו, ותמונת העמוד אם הוא עבר OCR. איור מקורי (בלוק `figure`) מוצג חתוך וגדול בתוך השיעור, ולחיצה עליו פותחת את העמוד.
- **סימולטורים:** 15 סימולטורים מוכנים ב-`src/components/sims/` (מכ"ם, ל"א ומעקב), ואנימציות שהמורה כותב (בלוק `anim`), שמסומנות כ"שרטוט של המורה".
- **תלת-ממד:** בלוק `scene3d` מהרכיב המשותף `shared/scene3d/`: עשר סצנות בדוקות (מערך מופע, GPS ו-DOP, התאבכות, גוף קשיח, אופק מכ"ם ומיסוך שטח, ניווט יחסי בתלת-ממד, מסלול בליסטי עם גרר ורוח, כיסוי קרקעי של לוויין, RCS של לוח, חתימת IR של מטוס), או מפרט JSON של המורה.
- **קריאה ארוכה:** כפתור Aa (גופן, גודל, ריווח, רוחב, רקע, מצב ריכוז), פס התקדמות, חזרה למקום שבו הפסקתם לקרוא, ותוכן שיעור צף עם זמן הקריאה שנשאר.
- **הנתונים שלך** במסד הנתונים של ה-Artifact, בתיקייה הפרטית `data/users/<id>/`:
  - `profile`: זיכרון הקורס (`memory`), המודולים שנלמדו (`done`), והמודול האחרון (`current`).
  - `profile/modules/<מודול>`: חלוקת השיעורים, השיעורים שהושלמו, מזהי השיחות והציון במבחן.
  - `profile/convs/<cid>` ו-`profile/convs/<cid>/msgs/<mid>`: השיחות וההודעות.

## הספרייה בדף

הטקסט, האיורים ותמונות העמודים מתפרסמים יחד עם ה-Artifact בתיקייה `lib/`, ונטענים לפי הצורך (ונשמרים ב-IndexedDB):

| קובץ | מה יש בו |
|---|---|
| `lib/index.json` | המסמכים, החלקים, המודולים עם הסעיפים שבעמודים שלהם, ו-`version` |
| `lib/text/<doc>.json` | טקסט לכל עמוד PDF, התווית המודפסת, וסימון של עמודים שעברו OCR |
| `lib/fig/<doc>-<k>.json` | האיורים החתוכים (WebP כ-data URI), בחבילות של כ-6MB |
| `lib/pg/<doc>-<k>.json` | תמונות של עמודים שעברו OCR, כי הנוסחאות בטקסט שלהם לא אמינות |
| מאגר הקבצים (`/_blob/...`) | האיורים ותמונות העמודים של SMAD, שלא נכנסים ב-256MB של גרסה. הכתובות ב-`core/tools/asset_urls.json` ובשדה `assets` של האינדקס |

איך מייצרים אותם:

```bash
# venv עם rapidocr_onnxruntime, scipy, pillow, numpy, pypdf
python3 -m venv ~/ocr-venv && ~/ocr-venv/bin/pip install rapidocr_onnxruntime scipy pillow numpy pypdf pymupdf
apt-get install -y tesseract-ocr   # OCR טוב יותר לעמודים מצולמים (בלעדיו: RapidOCR)

~/ocr-venv/bin/python core/tools/extract/extract.py          # כל המסמכים (ממשיך מאיפה שנעצר); או רשימת מסמכים
~/ocr-venv/bin/python core/tools/pack.py                     # כותב את core/app/artifact/lib/
```

החילוץ לוקח כשעתיים על 4 ליבות, וכדאי להריץ כמה תהליכים במקביל, כל אחד על מסמכים אחרים. `core/build/` ו-`core/app/artifact/lib/` לא נשמרים ב-git.

## פיתוח ובדיקה

```bash
cd core/app
npm install
npm run build                                   # dist/app.js + dist/app.css
node tools/test/make-harness.mjs /tmp/harness   # דף בדיקה עם runtime מדומה
cd /tmp/harness && python3 -m http.server 5190  # http://localhost:5190/test.html
```

ה-stub (`tools/test/stub.js`) מחקה את `sample` (חלוקת מודול, תכנון שיעור, שלושה חלקים כשאחד מהם נקטע, מבחן עם ציון), את `db` (נשמר ב-localStorage בין טעינות) ואת `user`. בדקנו עם Playwright ברוחב 1700px וברוחב 390px, בהיר וכהה: חלוקה לשיעורים, שיעור מלא, טעינה מחדש באמצע שיעור והמשך מהחלק השלישי, סימון המודול כנלמד, מציג המקורות, מבחן וציון.

## פרסום

הדף הוא `artifact/index.html`, עם `dist/app.js`, `dist/app.css` וכל הקבצים שב-`artifact/lib/`. הכול יחד כ-210MB, ולכן מפרסמים בכמה פעימות לאותה כתובת (עד 64MB בכל פעימה). החבילות שב-`artifact/assets/` מועלות למאגר הקבצים (ראו BUILD_GUIDE, סעיף 11.5). ההרשאות: `sample` (עם תמונות), `db`, `user`, `assets` ו-`downloads`. פרטים ב-[`docs/BUILD_GUIDE.md`](../../docs/BUILD_GUIDE.md).
