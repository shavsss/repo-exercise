# איך נבנתה מעבדת הלמידה (ואיך לבנות עוד אפליקציה כזו)

המסמך מתעד את הבנייה עד הפרט האחרון: מה נבנה, למה כל החלטה התקבלה, אילו מגבלות של claude.ai גילינו בדרך, ומה צריך כדי לחזור על זה במאגר חדש. בסוף יש הנחיה מוכנה להדבקה לסשן חדש של Claude Code.

---

## 1. התמונה הכללית

| שכבה | מה יש בה |
|---|---|
| **דף** | אפליקציית React שנבנית ל-JS אחד ול-CSS אחד, ומתפרסמת כ-Artifact פרטי ב-claude.ai, תמיד באותה כתובת |
| **Claude** | `claude.use("sample")`. הקריאה רצה על החשבון של מי שצופה, ולכן אין מפתח API ואין שרת |
| **נתונים** | `claude.use("db")` ו-`claude.use("user")`. כל משתמש מקבל תיקייה פרטית `data/users/<id>/...` |
| **תוכן גדול** (הספרים) | קובצי JSON שמתפרסמים ליד הדף (`books/*.json`) ונקראים ב-`fetch` יחסי |
| **גיבוי** | משימה מתוזמנת ב-Claude Code שקוראת את ה-db עם ArtifactData, כותבת MD ו-JSON, ועושה commit לענף `study-notes` |

### למה Artifact ולא שרת

הגרסה הראשונה הייתה Express עם Anthropic SDK. היא עבדה, אבל דרשה מפתח API, הרצה מקומית ותשלום נפרד. ב-Artifact הקריאות ל-Claude נספרות מהמנוי, הנתונים נשמרים בענן של claude.ai, והקישור עובד מכל מכשיר. המחיר הוא כמה מגבלות (סעיף 3), ובשבילן נבנו הפתרונות שבסעיף 5.

## 3. מה שגילינו על Artifacts (המגבלות, והתגובה לכל אחת)

| מגבלה | מה עשינו |
|---|---|

| הפרסום דוחה קבצים עם התו U+FFFD | `scripts/escape-bundle.mjs` מחליף אותו ב-`�` אחרי build. ספריות markdown משתמשות בו בכוונה |
| `confirm()`, `alert()` ו-`prompt()` לא עובדים | אישור בתוך הדף (למשל "מחק / ביטול" בשורת השיחה) |

| `sample` לא זוכר כלום בין קריאות | כל קריאה בונה מחדש: הנחיות, זיכרון קורס, היסטוריה שנכנסת, והתור החדש |
| קלט עד 256KB לכל קריאה (כולל תוצאות כלים) | תקציב של 170KB להיסטוריה. ההודעות הישנות נחתכות ראשונות, וזיכרון הקורס משלים את מה שנחתך |
| כל סבב מוגבל לכ-5 דקות; תשובה ארוכה נקטעת (`truncated`) | שיעור נכתב בחלקים (סעיף 5.2), ותשובה שנקטעת ממשיכה לבד (5.3) |
| כלים: מספר סבבים קטן, תוצאה עד 32KB לכלי | כלים מעטים: read_book_pages (כ-8 עמודים), search_book, compute, record_progress. העמודים שסביב המיקום נשלחים מראש בהקשר, כדי לחסוך סבבים |
| אין Python ואין אינטרנט בתוך הדף | חישובים ב-math.js, גם בכלי `compute` וגם בגרפים ובטבלאות, שמוגדרים כביטויים והדף מחשב אותם |
| מסמך db עד 256KB; עד 25,000 מסמכים; זוגיות נתיבים (זוגי = מסמך, אי-זוגי = אוסף) | מסמך לכל הודעה: `data/users/<id>/profile/convs/<cid>/msgs/<mid>` |
| `data/users/<id>` פרטי לגמרי, גם מהבעלים; `<id>` = `await user.id()` | צריך להצהיר על `user` ליד `db` |
| הצופה קובע את ערכת הצבעים (`data-theme` על השורש) | אין מתג צבעים בדף. `theme.ts` מאזין ל-`data-theme` ול-`prefers-color-scheme` |
| `localStorage`/IndexedDB רק לנוחות מקומית | רק לבחירות קטנות (ספר פעיל, מצב, תרגילים שנפתרו). כל מה שחשוב שמור ב-db |

## 4. הבנייה, צעד אחר צעד

### 4.1 שלד

```bash
npm create vite@latest app -- --template react-ts   # או ידנית כמו כאן
cd app
npm i react react-dom react-markdown remark-gfm remark-math rehype-katex katex mathjs recharts mermaid dompurify
npm i -D vite @vitejs/plugin-react typescript @types/react @types/react-dom @types/dompurify @types/node
```

### 4.2 build לקובץ אחד: `vite.config.ts`

```ts
export default defineConfig({
  plugins: [react()],
  base: "./",
  build: {
    assetsInlineLimit: () => true,        // גופנים ותמונות בתוך ה-CSS/JS
    cssCodeSplit: false,
    rolldownOptions: {
      input: "src/main.tsx",
      output: { inlineDynamicImports: true, entryFileNames: "app.js", assetFileNames: "app[extname]" },
    },
  },
});
```

ב-`package.json`: `"build": "vite build && node scripts/escape-bundle.mjs"`.

### 4.3 הדף: `artifact/index.html`

בלי `<!doctype>`, `<html>`, `<head>` ו-`<body>`, כי כלי הפרסום מוסיף אותם:

```html
<title>שם קצר</title>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=…&display=swap">
<link rel="stylesheet" href="app.css">
<style>html,body,#root{height:100%}</style>
<div id="root" dir="rtl" lang="he"></div>
<script type="module" src="app.js"></script>
```

### 4.4 החיבור ל-runtime: `src/runtime.ts`

הדפוס:

```ts
const use = (n) => window.claude?.use(n).catch(() => null) ?? Promise.resolve(null);
const [sample, db, user] = await Promise.all([use("sample"), use("db"), use("user")]);
const uid = user ? await user.id() : null;
const store = db && uid ? new Store(db, uid) : null;   // null → האפליקציה עובדת בלי שמירה
```

- כל יכולת יכולה להיות `null`. הדף מציג הודעה ולא נשבר.
- `Store` עוטף את הנתיבים: `profile` (התקדמות וזיכרון), `convs`, `msgs`. מנויים (`onSnapshot`) נפתחים פעם אחת בלבד, ב-`useEffect`.
- כתיבה אחת בכל פעם לכל מסמך. כאן זה נעשה עם שרשרת promise.

### 4.5 הקריאה ל-Claude: `src/tutor.ts`

```ts
sample([{ role: "user", content: SYSTEM_PROMPT }, ...history, { role: "user", content: studyContext + text }], {
  model: "claude-opus-5-5", modelTier: "complex", effort,   // מודל בשם רק כי המשתמש ביקש אותו
  signal, tools, onText: ({ text }) => render(text),         // text = כל התשובה עד עכשיו
});
```

- `onText` מקבל את **כל** הטקסט עד עכשיו, ולכן מציבים אותו ולא מוסיפים.
- `tools`: לכל כלי `name`, `description`, `inputSchema` ו-`execute`. `execute` רץ בדף ומחזיר נתונים קטנים, ושגיאה זורקים.
- עם `tools` אסור `cache` (מלבד `false`).
- שגיאות מגיעות כ-`{code, message, text?}`. מטפלים לפי `code`, ולא מנסים שוב בלולאה.

### 4.6 התצוגה

- Markdown עם KaTeX (`remark-math` + `rehype-katex`). מעטפת RTL, ו-`.katex { direction: ltr }`.
- **בלוקים מותאמים:** fence עם שם (```` ```story ````), כותרות `@key: value` בראש הבלוק, וגוף Markdown. הרכיב `pre` ב-react-markdown מנתב לפי השפה.
- **תגיות בתוך הטקסט** (`[[ודאות: גבוהה]]`): לפני הפענוח הן הופכות ל-inline code עם סימן, ונצבעות כ-pill.
- **גרפים וטבלאות:** JSON עם ביטויי math.js, והדף מחשב את הערכים. כך אי אפשר "להקליד" מספר לגרף.
- **אינטראקטיבי:** מחוונים, ועקומים מפורשים, פרמטריים או מובלעים (marching squares) ב-SVG.

## 5. הפתרונות שחשובים לכל אפליקציה כזו

### 5.1 הנחיות כתור ראשון, והקשר בתור האחרון

ההנחיות קבועות. כל מה שמשתנה (תאריך, מיקום בספר, זיכרון, עמודים) נכנס לבלוק `<study_context>` בתחילת התור האחרון, וההנחיות אומרות למודל להתייחס אליו כמצב של האפליקציה.

### 5.2 תוכן ארוך: תכנון ואז חלקים (`composeLesson`)

1. קריאת `sample.json` עם כלים, שמחזירה תוכנית: חלקים עם כותרת, מה כל חלק מכסה, אילו בלוקים יופיעו, יעד מילים, ועובדות מחושבות.
2. קריאה נפרדת לכל חלק. כל אחת מקבלת את התוכנית ואת כל הטקסט שנכתב עד עכשיו, עם הוראה להמשיך מהמשפט האחרון בלי לחזור על כלום.
3. החלק האחרון סוגר: תרגילים, מוצר, משפט על ההודעה הבאה, ו-`record_progress`.

ככה האורך מובטח בתוכנית, ואף קריאה לא מתקרבת למגבלת הזמן.

### 5.3 המשך אוטומטי

אם `truncated: true`, נשלחת קריאה נוספת: ההיסטוריה, התשובה החלקית כתור assistant, והוראת "המשך בדיוק מהמקום שנעצרת". התוצאה מצורפת להודעה. עד 4 חלקים.

במעבדת הליבה ובגילואה גם התוכן נבדק (`src/truncation.ts`, זהה בשתיהן, עם בדיקות ב-`tools/test/truncation.test.mjs`): טקסט שנגמר באמצע משפט, בכותרת, בבלוק ``` פתוח, ב-`$$` או ב-`[[` פתוחים נחשב קטוע גם בלי `truncated`. חלק של שיעור מקבל עד שני המשכים, ותשובה רגילה עוד המשך אחד. `joinContinuation` מחבר את ההמשך בלי לחזור על הסוף שכבר נכתב.

### 5.4 טיוטות ושחזור

- כל תשובה נשמרת כמסמך עם `draft: true`: מיד בהתחלה, אחרי התוכנית, אחרי כל חלק, וכל 8 שניות של טקסט.
- טיוטה שנמצאת בפתיחה = תשובה שנקטעה. "המשך" קורא ל-`generate` עם `resume`: בשיעור הוא ממשיך מהחלק `partsDone` לפי אותה `plan`, ובתשובה רגילה ממשיך את הטקסט.
- בסיום הטיוטה הופכת להודעה רגילה (`draft`, `plan` ו-`partsDone` נמחקים).

### 5.5 זיכרון מתגלגל

אחרי כל שיעור, קריאה קצרה (`modelTier: "default"`) מקבלת את הזיכרון הקיים ואת השיעור, ומחזירה זיכרון מעודכן עם סעיפים קבועים. הזיכרון נשמר ב-`profile.memory`, נשלח בכל בקשה, ואפשר לערוך אותו בממשק.

### 5.6 שיחה לכל סעיף

"השיעור הבא" פותח שיחה חדשה, חוץ מכשהסעיף האחרון נשמר עם "(חלק k/n)" ו-k קטן מ-n. ההיסטוריה נשארת קצרה, והרציפות עוברת דרך הזיכרון.

## 6. בדיקה מקומית

```bash
cd app
npm run build
node tools/test/make-harness.mjs /tmp/harness
cd /tmp/harness && python3 -m http.server 5190     # http://localhost:5190/test.html
```

ה-stub מחקה את `sample` (כולל `json` וכלים), את `db` (נשמר ב-localStorage בין טעינות, כך שאפשר לבדוק סגירה ופתיחה) ואת `user`. את המסלולים בדקנו עם Playwright (מותקן מראש בסביבת הענן):

- טעינת PDF ומספור עמודים
- שיעור בחלקים, כולל חלק שנקטע וממשיך
- שמירת התקדמות וזיכרון
- סגירה באמצע ושחזור
- גרף וטבלה מחושבים

ה-stub לא מחליף בדיקה אמיתית ב-claude.ai, כי אישורי ההרשאה, מגבלות הזמן והתוכן האמיתי של Claude קיימים רק שם.

## 11. מעבדת הליבה: מה נוסף בשנייה

מעבדת הליבה (`core/`) נבנתה באותה שיטה, כ-Artifact נפרד. ההחלטות שלה ב-[`CORE_LAB_PLAN.md`](CORE_LAB_PLAN.md), והכללים ב-[`CORE_TEACHING_RULES.md`](CORE_TEACHING_RULES.md). מה שונה ממעבדת הלמידה:

| נושא | מעבדת הלמידה | מעבדת הליבה |
|---|---|---|
| יחידת הלימוד | סעיף בספר, לפי עמוד | מודול מתוכנית הלימודים, מחולק לשיעורים |
| מקורות | 6 ספרים | 49 מסמכים: 14 ספרים, 31 מאמרים ו-4 מסמכי דוקטרינה |
| טקסט | `pdftotext` | `pdftotext`, ו-OCR לעמודים בלי שכבת טקסט (Tesseract כשהוא מותקן, אחרת RapidOCR) |
| איורים | שחזור ב-svg | האיור המקורי, חתוך מהעמוד, ועוד שחזור כשצריך |
| התקדמות | עמוד בכל ספר | מודולים שנלמדו, ושיעורים שהושלמו בכל מודול |
| ערכת צבעים | לפי הצופה בלבד | לפי הצופה, ועם מתג בדף שגובר עליו |

### 11.1 הספרייה

- `core/tools/extract/extract.py` עובר על כל עמוד: טקסט עם `pdftotext`, OCR כשיש פחות מ-15 מילים או כששכבת הטקסט מתפענחת לתווי בקרה כמעט בלי מילים (גופני Type-3 בלי מיפוי Unicode, כמו ב-Trefethen & Bau; עמוד שרק הסמלים במשוואות שלו משובשים שומר על הטקסט), תוויות עמוד מודפסות (מספר שמסכים עם ההיסט של השכנים), ואיורים. איור מזוהה לפי הכיתוב שלו ("Figure 2-8") ולפי תמונות מוטמעות: העמוד מרונדר, הטקסט הרץ נמחק, הדיו שנשאר מקובץ לרכיבים, והרכיב הקרוב לכיתוב נחתך ונשמר כ-WebP.
- **OCR:** כש-`tesseract` מותקן (`apt-get install tesseract-ocr`), העמוד מרונדר ב-300dpi, התאורה שלו מיושרת (כל פיקסל מחולק בטשטוש כבד של סביבתו, כך שצל ורקע כהה הופכים ללבן), ו-Tesseract קורא אותו. כך העמודים של ספר מצולם יוצאים עם רווחים בין מילים ועם עמודות בסדר הנכון; RapidOCR מדביק מילים ומערבב עמודות. ב-SMAD, כ-96% מהמילים הן מילים מהמילון. גם זיהוי האיורים בעמוד סרוק עובד על התמונה המיושרת, אחרת הרקע הכהה של הצילום נראה כמו איור אחד בגודל העמוד.
- **מסמך בכמה קבצים:** ספר גדול מ-100MB (המגבלה של GitHub לקובץ) נשמר כתיקייה של חלקים (`books/12_SMAD/SMAD_0001-0100.pdf`...), ו-`DOCS` מצביע על התיקייה. `core/tools/source_pdf.py` מחבר את החלקים לפי סדר השמות לקובץ אחד ב-`core/build/merged/` (עם `pdfunite`), ו-`build.py` סופר את העמודים של כל החלקים.
- **תוויות עמוד קבועות:** בעמודים מצולמים, "Table 7-9" נראה כמו תווית פרק-עמוד. למסמך כזה מגדירים ב-`LABEL_OFFSETS` שב-`extract.py` את ההיסט בין עמוד PDF לעמוד מודפס בכל טווח.
- **כמה תהליכים על מסמך אחד:** `EXTRACT_OUT=<dir> extract.py DOC --pages A-B` כותב לתיקייה נפרדת. אחר כך מאחדים את `pages.json`, `figures.json` ואת קובצי האיורים, ומריצים `resolve_labels` על הכול.
- הסקריפט שומר כל 40 עמודים וממשיך מאיפה שנעצר. כדאי להריץ כמה תהליכים במקביל, כל אחד על מסמכים אחרים (תור עם `xargs -P 4`), ולשים את המסמכים הגדולים ראשונים. שני תהליכים על אותו מסמך דורסים זה את זה.
- `core/tools/pack.py` אורז ל-`core/app/artifact/lib/`: אינדקס, טקסט לכל מסמך, ואיורים ותמונות עמודים בחבילות של כ-6MB. זה עוזר כי לפרסום יש מגבלה של 255 קבצים בכל פעימה ו-16MB לקובץ טקסט. הסעיפים של כל מודול נלקחים מתוכן העניינים של ה-PDF כשהוא מגיע לרמת סעיפים (בערך כותרת לכל 8 עמודים). אחרת הם נלקחים מכותרות ממוספרות בטקסט (גם מספר בשורה נפרדת מהכותרת), ואם גם אין כאלה, לפי גודל הגופן. עמודים שב-SKIP (תוכן עניינים) וכותרות רצות לא נספרים.
- **מסמך אחד על אינדקס שפורסם:** `PACK_OUT=<dir>/lib python core/tools/pack.py --only DOC --base <lib/index.json שפורסם> --keep-modules` כותב את קובצי המסמך (חבילות של `ASSET_DOCS` ל-`<dir>/assets`) ואינדקס שבו רק המסמכים השתנו. `core/tools/merge_index.py --base <אינדקס> --src <האינדקס הזה> --docs DOC [--asset-urls core/tools/asset_urls.json] --out <קובץ>` מעתיק את אותן רשומות לכל אינדקס אחר (גם של גילואה), כך ששינוי מודולים ושינוי מסמכים נכנסים בכל סדר.
- הדף טוען את `lib/index.json` בלי cache, ואת שאר הקבצים לפי הצורך. הם נשמרים ב-IndexedDB לפי ה-`version` שבאינדקס, כך שאחרי אריזה חדשה הם נטענים מחדש.

### 11.2 מודול, שיעור ומבחן

- **חלוקה:** `planModule` מקבל את רשימת הסעיפים ואת העמוד הראשון של כל מקור, ומחזיר רשימת שיעורים. `uncoveredSections` בודק שכל סעיף שויך, ו-`uncoveredPages` בודק שכל עמוד של מקור ראשי או השלמה נמצא בטווח של שיעור כלשהו. הבדיקה השנייה עובדת גם במקור שלא זוהו בו כותרות. אם חסר, יש ניסיון שני עם מה שחסר, ומה שעדיין חסר מצורף לשיעור הקרוב.
- **שיעור:** כמו `composeLesson` במעבדת הלמידה (תכנון ואז חלקים), אבל עם עמודי המקור של השיעור בהקשר (עד כ-95KB), ועם הכלים `read_source_pages`, `search_library` ו-`compute`.
- **נלמד:** אין `record_progress`. האפליקציה מסמנת שיעור כהושלם כשהוא נכתב עד הסוף בלי שגיאה, ומודול כנלמד כשכל השיעורים שלו הושלמו.
- **מבחן:** `askTutor` במצב `quiz`. הציון נלקח מהתגית `[[ציון: N/100]]`.

### 11.3 תצוגה

- **תגיות מקור:** `[[DOC:PAGE]]` הופך לכפתור שמציג את השם הקצר ואת התווית המודפסת (נטענת מטקסט המסמך), ופותח את מציג המקורות.
- **בלוקים חדשים:** `figure` (איור מקורי בגיליון שרטוט עם בלוק כותרת: שם, מספר איור בשיעור, מקור ועמוד), `sim` (סימולטור מהקטלוג), `anim` (אנימציה מביטויי math.js), `coverage` ו-`fieldsystems`.
- **משוואה בשורה אחת:** `$$…\tag{1}$$` בשורה אחת הופך לבלוק לפני הפענוח. בלי זה remark-math קורא אותו כמתמטיקה בתוך השורה, ו-KaTeX דוחה את `\tag`.
- **ערכת צבעים:** `theme.ts` שומר בחירה מקומית ב-localStorage, כותב אותה ל-`data-theme`, ומחזיר אותה אם המארח משנה את התכונה. ה-CSS מגדיר את הגרסה הכהה פעמיים: תחת `prefers-color-scheme` (כשאין `data-theme="light"`), ותחת `data-theme="dark"`.
- **קנבס:** סימולטורים מצוירים על `<canvas>` עם `direction: ltr`. בלי זה, בדף RTL המינוס של מספרים שליליים בצירים עובר לצד הלא נכון.

### 11.4 פרסום בכמה פעימות

הספרייה ארוזה גדולה מ-64MB, וזו המגבלה של פעימת פרסום אחת:

1. פעימה ראשונה: `file_path: core/app/artifact/index.html`, עם `app.js`, `app.css` ו-`lib/index.json`, וגם `capabilities: {sample: {images: true}, db: {}, user: {}}`, `icon` ו-`description`.
2. הפעימות הבאות מתפרסמות לאותה כתובת (`url`), כל אחת עם חלק מקבצי `lib/` (עד 64MB ו-255 קבצים). קבצים שלא נשלחים נשארים מהגרסה הקודמת.
3. עדכון קוד בלבד: `app.js` ו-`app.css`. אחרי אריזה חדשה צריך לפרסם מחדש את כל הקבצים שהשתנו ואת `lib/index.json`.

### 11.5 מאגר הקבצים (assets): מעבר ל-256MB

גרסה של Artifact מוגבלת ל-256MB ול-511 קבצים. עם SMAD הספרייה עברה את זה, ולכן האיורים ותמונות העמודים של המסמכים שב-`ASSET_DOCS` (ב-`pack.py`) נשמרים במאגר הקבצים של ה-Artifact, שלא נספר בגרסה:

1. הדף מצהיר גם על `assets: {}` בהרשאות.
2. `pack.py` כותב את החבילות שלהם ל-`core/app/artifact/assets/` ולא ל-`lib/`.
3. כל חבילה מועלית בקריאה משלה: `Artifact` publish עם `url`, `file_path` של החבילה ו-`asset: true`. התוצאה היא כתובת `/_blob/<id>`.
4. הכתובות נשמרות ב-`core/tools/asset_urls.json` (ב-git), ו-`pack.py` כותב אותן לשדה `assets` של `index.json`. `library.ts` טוען חבילה מהכתובת שלה כשיש כזו, ואחרת מ-`lib/`.
5. בבדיקה המקומית, `stub.js` מגיש את הכתובות האלה מתיקיית `assets/` של דף הבדיקה.

כשחבילה משתנה, מעלים אותה שוב ומעדכנים את הכתובת. כדאי למחוק את הקודמת (`action: "delete"` עם ה-id).

### 11.6 תקציב המסמכים (25,000 למסד)

אוסף שגדל בלחיצה (מסמך לכל אירוע) ממלא את המסד בתוך שנה, ולכן כל אוסף גדל בימים או בשיעורים, וכל מסמך נשאר מתחת לכ-200KB (נמדד בבתים של UTF-8, `jsonBytes`/`utf8Bytes`):

| אוסף | מבנה | מסמכים |
|---|---|---|
| `events` | מסמך ליום, `entries` (500 האחרונים) | 1 ליום |
| `usage` | מסמך ליום, `sessions` (40 בשם, השאר מסוכמים ב-`_older`) | 1 ליום |
| `calib` | מסמך לשיעור, `items` לפי שאלה | 1 לשיעור |
| `consults/<key>` + `cards/pack-<n>` | כמה כרטיסים בחבילה, עד 180KB | 2 לשיעור בדרך כלל |
| `memlog` | גרסה למסמך 30 יום, ואחר כך מסמך חודש `m-<YYYY-MM>` | כ-100 + 1 לחודש |
| `convs/<cid>/msgs` + `more/<n>` | הודעה למסמך, וההמשך כשהיא עוברת 200KB עם כל השדות | 2–4 לשיעור, ועוד 2 לכל שאלה |

שיעור עולה בערך 10–25 מסמכים (כולל מחברת, פתקים, שרטוטים ורמה 3), כלומר מקום לכ-1,000 שיעורים ומעלה. הקוראים מקבלים גם את הפורמט הראשון (מסמך לאירוע, לשאלה, לכרטיס, ל-`<יום>__<סשן>`).

## 12. מעבדת ההנדסה: מה נוסף בשלישית

מעבדת ההנדסה (`eng/`) היא עותק של מעבדת הליבה עם שינויים, ולא אפליקציה שנבנתה מאפס. ההחלטות שלה ב-[`ENG_LAB_PLAN.md`](ENG_LAB_PLAN.md), והכללים ב-[`ENG_TEACHING_RULES.md`](ENG_TEACHING_RULES.md).

### 12.1 מה הועתק ומה שונה

- `eng/app/` הועתק מ-`core/app/` (בלי `node_modules`, `dist` ו-`lib`). המפתחות ב-localStorage ושם ה-IndexedDB הוחלפו ל-`eng-lab`, כדי ששתי האפליקציות לא ידרסו זו את זו כשהן פתוחות באותו דפדפן.
- `prompt.ts` נכתב מחדש: רמה 2.5, תגיות `[[2.5: …]]`, בלוק `today` במקום `fieldsystems`, בלוקים `derivation` ו-`notebook`, ותחומי `domain` של הנדסה. `segments.ts` בודק את שבע התגיות.
- תפקיד מקור חדש, `ex`: עמודי תרגילים. הם לא נכנסים לבדיקת הכיסוי של החלוקה לשיעורים (`uncoveredPages`), ולא לעמודים שנשלחים עם השיעור.
- הסעיפים של כל מודול באים ממפות `toc/` של תוכנית הלימודים, ולא מתוכן העניינים של ה-PDF.

### 12.2 הספרייה

- `eng/tools/extract.py` משתמש במחלץ של מעבדת הליבה כמו שהוא, ומחליף רק את רשימת המסמכים ואת תיקיית הפלט. קולמוגורוב ופיינמן I–II נלקחים מקבצי הטקסט של מעבדת הלמידה. מסמך סרוק ארוך מחלקים לטווחי עמודים (`EXTRACT_OUT=<dir> extract.py DOC --pages A-B`) ומאחדים עם `eng/tools/merge_parts.py`.
- `eng/tools/pack.py` בוחר בעצמו אילו מסמכים יעברו למאגר הקבצים: הכבדים ביותר, עד ש-`lib/` נכנס ב-`LIB_BUDGET` (215MB). החבילות שלהם גדולות יותר (עד 18MB), כדי שיהיו פחות העלאות.

### 12.3 רכיב התלת-ממד המשותף

`shared/scene3d/` הוא TypeScript בלי React ובלי תלויות npm, ושתי האפליקציות מייבאות אותו (ה-`tsconfig` שלהן כולל את `../../shared`). כל אפליקציה עוטפת אותו בבלוק React משלה (`components/blocks/Scene3D.tsx`, אותו קובץ בשתיהן).

- **טעינה עצלה:** three.js r128 (UMD) ו-OrbitControls ו-RoomEnvironment נטענים מה-CDN רק כשסצנה מתקרבת למסך. ה-bundle של האפליקציה לא גדל.
- **renderer אחד:** כל הסצנות בדף מצוירות ב-WebGLRenderer יחיד מחוץ למסך, עם viewport ו-scissor בגודל הסצנה, והתמונה מועתקת (`drawImage`) לקנבס דו-ממדי של הסצנה. כך אין מגבלה של כ-16 הקשרי WebGL לדף, ורק סצנות שעל המסך מצוירות.
- **ספריית סצנות:** `scenes.ts`. כל סצנה מחושבת מהפיזיקה של המודול, עם פרמטרים (מחוונים), שורת מספרים בפינה (`hud`), סיור מודרך ו-`info` על כל חלק. לחיצה קצרה (פחות מ-6 פיקסלים של תזוזה) עושה raycast ומציגה את ה-`info`.
- **מפרט של המורה:** `spec.ts`. JSON עם נוסחאות, בלי קוד: משטח, עקומה, וקטור, נקודה עם מסלול, שדה וקטורי ומישור. הנוסחאות עוברות מהדר קטן משלו, כך שאין `eval`. הקואורדינטות מתמטיות (z למעלה) ומומרות לצירים של three.js.
- **טלפון:** רזולוציה עד 1.5, מפות צל קטנות ורשתות דלילות. במגע, הסצנה לא תופסת את הגלילה עד שמקישים עליה.
- **בדיקה:** `make-harness.mjs` כותב גם `scenes.html`, שיעור שמציג את כל סצנות הספרייה.

### 12.4 מחברת השיעור

בשתי האפליקציות. פריטים ב-`profile/notes/<id>`: מי כתב (הלומד או המורה), סוג (רעיון למאמר, שאלה לראיון, להעמקה, הערה), הטקסט, המודול והשיעור. המורה שומר עם הכלי `save_lesson_note`, ורואה את המחברת של השיעור ב-`<lesson_notebook>` שבהקשר. הייצוא ל-Markdown עובר דרך ההרשאה `downloads`, וגם הגיבוי לגיט כותב `NOTEBOOK.md`.

### 12.5 הורדת קבצים

ההרשאה `downloads` מקבלת רק סיומות מרשימה מוגדרת, ו-`ipynb` לא ביניהן. לכן המחברת המעשית יורדת כ-zip שבתוכו ה-ipynb (`src/zip.ts` כותב zip בלי דחיסה), וייצוא המחברת יורד כ-md.
